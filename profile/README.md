<p>试水期最怕的不是慢，而是花了钱拿到一堆重复线路，等发现时已经用了一周。这篇把「试水期踩坑」当成一个顶层故障事件，往下拆成三个分支：IP 重复、可用性差、资源被回收。每个分支给出现象、中间原因、基本原因和可以直接执行的验证命令，最后把这棵故障树倒过来，变成一份选型核对清单。</p>

<h2>一、顶层现象拆成三类，先定位方向</h2>
<p>遇到问题先分方向，别一上来就联系服务商换线路。方向错了，换十次也解决不了。</p>
<h3>三类现象的特征</h3>
<p>IP 重复的表现是「部分号出问题、且这些号的出口在同一网段」；可用性差的表现是「所有号都慢或都掉、集中在固定时段」；资源被回收的表现是「线路突然失效、控制台里显示已释放或已更换」。</p>
<h3>为什么先查重复，用什么命令查</h3>
<p>因为重复是最常见的，也最容易被误判成「平台风控」。池子小时，服务商给十个号发三条线的地址，落在同一 /24 的概率相当高，一旦同段里有一个号出问题，其余号跟着受牵连。</p>
<p>先批量查一遍：curl --proxy 用户:密码@地址:端口 -s https://ipinfo.io/json，把返回的 ip 和 org 存成表。org 里的 ASN 相同的超过三条，就进入分支一。</p>

<h2>二、分支一：IP 重复，同段撞车怎么查</h2>
<p>这个分支的排查路径最短，二十分钟能出结论。</p>
<h3>中间事件：网段集中</h3>
<p>把拿到的 IP 转成整数后比前 24 位，或者直接用在线工具看 CIDR。十条线里超过两条落在同一 /24，就属于网段集中。这在共享池里很常见，在标称独享的方案里出现，说明服务商在做地址复用。</p>
<h3>基本事件：池子小、分配逻辑随机</h3>
<p>池子小是根因。按碰撞概率估算，20 个号从 50 个出口里分配，出现至少一组重复的概率接近 100%。所以「池子大」不是营销词，是能算出来的硬指标。</p>
<h3>验证与处置</h3>
<p>用 ipinfo 的 org 字段加 bgp.he.net 查 ASN 归属，确认是否同一运营商同一段；再用 whois 看分配时间，同一时间批量分配的地址往往连号。处置方式是要求按 /24 分散分配，或者直接换池子。</p>

<h2>三、分支二：可用性差，从延迟追到丢包</h2>
<p>「慢」有三种完全不同的成因，用同一个办法处理只会浪费时间。</p>
<h3>先分清是延迟高还是丢包</h3>
<p>mtr -rwc 20 目标地址，看最后几跳的 Loss% 和 Stdev。丢包率超过 2%、且集中在某一跳之后，是链路问题；丢包接近 0 但 Avg 很高，是距离或中转节点的问题。</p>
<h3>再看是不是时段性的</h3>
<p>连续三天在同一时段（当地 19:00–23:00）各测一次。晚高峰显著劣化、白天正常，基本可以判定为共享带宽被占满。这种问题换线路能解决，换配置解决不了。</p>
<h3>最后看是不是本机问题</h3>
<p>用 tcping 测代理端口的握手时间，和 mtr 的结果对比。握手就慢，说明问题在接入侧；握手快但传输慢，说明在出口侧。这个区分能省掉一半无效沟通。</p>

<h2>四、分支三：试水期资源被回收</h2>
<p>短周期套餐最容易出这类问题，而且往往在第二周才暴露。</p>
<h3>典型表现</h3>
<p>线路昨天还好，今天全部超时；控制台里显示的到期时间比预期早；同一个订单号下的地址被换成了另一批。这类问题不是技术故障，是商务条款没看清。</p>
<h3>提前确认条款，并留好证据</h3>
<p>要问三件事：试用套餐的有效期是按自然日还是按 24 小时计；到期后地址是否立即回收、能否续用同一批地址；短周期套餐是否限制每日流量或连接数，超限后是限速还是直接断。</p>
<p>每天固定时间把控制台的线路列表截图或导出成文本，附上时间戳。出现争议时，这份记录比口头沟通有用得多。同时把自己的使用日志保留至少 30 天。</p>

<h2>五、把故障树倒过来，变成选型清单</h2>
<p>每个基本事件都对应一条选型要求，这比看评测排名实在。</p>
<h3>五条硬要求</h3>
<p>池子规模至少是号数的 8 倍；同一订单内地址按 /24 分散；支持指定会话保持时长且可调；试用期不少于 7 天且到期可续用原地址；提供 ASN 与网段信息，允许自行核验。</p>
<h3>两条软要求</h3>
<p>有公开的线路状态页或公告渠道；有能说清技术细节的对接人，而不是只会说「很稳定的」。遇到问题能直接问「这批地址的 ASN 分布是什么」，对方答不上来，基本可以判断是小转售。</p>

<h2>常见问答</h2>
<h3>试水期只买一条线，能测出池子大小吗？</h3>
<p>答：测不出池子总量，但能测出分配逻辑。连续三天每天重新提取一次，看拿到的地址是否连号、是否落回同一段。连号说明是批量分配，实际可用范围比宣传的小。</p>
<h3>服务商说「独享」，但延迟曲线还是有规律尖峰，怎么回事？</h3>
<p>答：可能是共享上游带宽。IP 独享不等于带宽独享，一条家宽的上行本来就是共享的。要求对方说明单条线的带宽承诺值，并在合同里写明。</p>
<h3>同段撞车一定会出问题吗？</h3>
<p>答：不一定，但风险明显升高。同段里的其他地址如果被用于违规操作，整段可能被平台重点关注。号多的时候，这种外部因素造成的损失往往比线路费更高。</p>
<h3>短周期试水该拿多少资源？</h3>
<p>答：拿目标规模的 10%–20%，但每条线都要单独验证。宁可五条线各跑两个号，也不要一条线跑十个号——后者测不出分配逻辑，也测不出撞段风险。</p>
